Purchase Return & Vendor Credit Wizard

Return goods to a vendor from any Purchase Order or receipt in a single popup. The wizard validates the return transfer and drafts the vendor credit note in one step, crediting only what was actually billed.

Why this module

Returning purchased goods in standard Odoo works, but it is slow and easy to get wrong when an order has many lines, several receipts or partial bills.

In standard Odoo 17

  • Returns start from one receipt at a time. With several receipts per PO you must find the right one first.
  • The return screen lists stock moves with no search, no filter and no view of what was billed.
  • The return transfer is created but still has to be checked and validated by hand.
  • The credit note is a separate step on the bill or PO, and you work out the billed part of each return yourself.
  • Partly billed lines are easy to over-credit, credit twice, or credit goods that were never billed.
  • Nothing ties a return transfer to its credit note and its reason in one audit record.

With this module

  • One Return / Refund button on the PO and on each validated receipt.
  • Every PO line in one table with ordered, received, billed and returnable quantities and a status badge.
  • Search and filter by product, SKU, barcode, quantity range or status. Built for POs with hundreds of lines.
  • A Review step, then one click: the return transfer is validated and a draft credit note is created.
  • Credit is limited to the billed portion of each return, recomputed live under a database lock.
  • An immutable PRET log links the PO, the receipt, the transfers, the credit note and the reason.

Features

All screenshots are from a live Odoo 17 database with fictional demo data.

Feature 1

Return / Refund button on the Purchase Order

Shown on confirmed and locked orders to users in the Process Returns group. The Returns smart button counts every return made for the order.

Feature 2

Every PO line in one table, with a live status per line

Each line shows Ordered, Received, Billed and Returnable quantities and a badge: Billed Partially Billed Not Billed Not Received.

Choose Keep or Return per line and type the exact quantity. Credit Amount previews what goes on the credit note before anything is created.

Feature 3

Search and filter large orders

Filter by product name, SKU or barcode, by a quantity range on Ordered, Received, Returnable or Billed, by status, or show only the lines marked for return. Filtering runs on the server, so only matching rows load and edits on hidden rows are kept. Return All Shown and Keep All Shown act on the filtered rows only.

Search “REBAR” matches the SKU: 2 of 12 lines shown.
Status = Billed: 4 of 12 lines shown.
Feature 4

Quantities can never exceed what was ordered or received

A quantity above the limit is capped while you type, with a message that explains why. Server-side constraints block negative values, Keep/Return mismatches and anything above ordered, received or still-returnable (pending returns are deducted). On confirm, every figure is re-read from the database under a row lock, so two users can't return the same goods.

Feature 5

Review before anything is posted

The Review step shows the documents that will be created, the total quantity, the untaxed credit amount and only the lines being returned. Go Back to change the selection, or Cancel and nothing is created.

Feature 6

One click: done, closed and linked

On Confirm Return the popup closes and the Purchase Order reloads with updated Received and Billed quantities. A notification links to the PRET log, each return transfer and the credit note. If any step fails, everything is rolled back.

Features 7 & 8

Validated return transfer and an exact draft credit note

The return is created with Odoo's standard return mechanism against the original receipt, so valuation and traceability follow core rules. It is validated straight away. The draft Vendor Credit Note holds one line per credited product at the average billed price with the bill's taxes. Each line is linked to its PO line, and the reference and reason point back to the PRET log.

Feature 9

Immutable audit trail: Purchase Returns

Every confirmed return writes a PRET/YYYY/NNNN record that nobody can edit or delete. It holds the processing user and date, the routing, the credit note and its live status, the amount credited, the returned lines and the reason. Find it under Purchase › Orders › Purchase Returns, with filters and grouping by vendor, routing or month.

Feature 10

Start from a receipt too

The same button sits next to Odoo's Return on every validated PO receipt. From a receipt, the wizard lists only the PO lines received in it, adds an In This Receipt column, and always returns against that receipt. Billing and credit stay at PO-line level, so the credit is still exact. A PO Returns smart button and chatter messages appear on the receipt.

Automatic routing

Each line is routed by what was received and billed for it. Only the part of a return that would leave the vendor over-billed is credited.

Line status Condition Created on confirm
Not BilledReceived > 0, nothing billedValidated return transfer
BilledBilled ≥ receivedValidated return transfer + draft credit note line
Partially Billed0 < billed < receivedReturn transfer for the full quantity; credit only for the billed part
Not ReceivedNothing receivedNothing (line is read-only)
Credit Qty = min(Q, max(0, B − (R − Q)))  where Q = returned, R = received, B = billed.
Example: received 500, billed 300, return 300 → 200 units are kept against 300 billed, so 100 are credited. Billed = posted bills − posted and draft credit notes, so a second return never credits the same units twice.

Built for real-world corner cases

Several receipts per PO
Returns are taken from the newest receipts first, with one return transfer per original receipt.
Concurrent users
PO lines are locked on confirm, and a stale wizard is refused with a clear message.
Pending returns
Returns not yet validated are deducted from what can still be returned.
Over-receipts
The return is capped at the ordered quantity, even when more was received.
Units of measure & currencies
Quantities are converted to the PO unit, and bill prices to the PO currency.
Draft vendor bills
Flagged with a warning in the wizard, never changed silently.
Unusual receipts
Receipts mixing POs, dropships, returns and manual lines are detected and explained.
Stock no longer on hand
The whole return is rolled back: no transfer, no credit note, no log.
Security & multi-company
A dedicated group controls access, and record rules apply per company.
